# Paired native replay with disk-backed Aerospike

## Registered workload and outcomes

Registered on 2026-11-21 before testing the alternate storage deployment. The comparator is the four-store SQLite run of 32 blocks with 16,384 signed payments each. A fresh isolated project uses the same stock SV Node v1.2.3 → Teranode v0.16.1 legacy → second Teranode native route. Scary Node uses both native interfaces. Each Teranode has its own network-isolated disk-backed Aerospike 8.1.2.0-1 UTXO service, nine GiB data file and independent blockchain, transaction and subtree stores. The Scary Node source is `af9b605ad8da96d041a540111d46a7c0105209f7`. The Linux packager at `6ad4152ee517bc282ac70af4b0550ff6ba4458bc` has the same Rust source and compiles in a fresh target directory. The release digest, image IDs, Docker resources and backing volume capacity are recorded with the trial. The first 451 exact regtest bodies establish the common funding state through the stock SV submission endpoint and native propagation. The entrant must witness the funding block at height 451 before the trial clock starts. The measured input is the original SQLite trial's ordered bytes at heights 452–483. All 32 source block hashes and body SHA-256 values must match the comparator before timing starts. The driver offers up to four blocks at once. Each recipient independently retrieves and processes the blocks. The offline verifier checks all 96 subsequent stock readbacks and all 524,288 witnessed input checks.

The registered target is 3,000 ordinary signed spends per second at both single-source ingress and final four-store adoption. Ingress is total signed spends divided by elapsed time from the first offer through the final SV acceptance. Four-store adoption extends that interval until polling observes the final hash at every recipient. Both include all source, receiver and backpressure waits. Final sampling times are upper bounds on arrival. Preparation, signature generation and retrospective byte readbacks are outside the throughput interval. A stopped or incomplete attempt stays in the attempt log and counts as an incomplete qualification. The first complete measured run supplies the reported result at this configuration, including a result below target.

The downstream node was lowest or tied for lowest in all 838 below-window polls on SQLite. At height 483 the stock downstream service logged 9.74 seconds in transaction-level processing and 38 milliseconds in body persistence. The directly connected Teranode logged 15.80 seconds for complete legacy block processing at the same height. This motivates changing the UTXO storage backend while preserving full validation, route, workload and window. Different entrant release binaries and any differences in observed infrastructure are disclosed with the two results.

## Reproducing the comparison

Retain the SQLite mixed project after its large workload. Use the original workload receipt to export the selected wire bodies into a local directory. The export verifies the funding linkage, proof of work, transaction Merkle commitments and every measured body digest. A different fresh SQLite run produces its own matched corpus. Use that run's receipt for both export and replay. The named Docker project `scary-node-throughput` is separate from the SQLite project and binds its ingress ports to loopback.
