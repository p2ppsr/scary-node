# Operating the alpha

Loss of all eligible data-peer connections withdraws outstanding work. The node reconfirms the current tip after reconnecting. SV peers can return bounded recent headers and bodies from the restored contemporary boundary. The status reports `connected_data_peers` and `tip_confirmed_since_disconnect`.

Synchronize the host clock before starting the node. The status fields `clock_step_seconds` and `clock_step_limit_seconds` compare wall time against monotonic elapsed time since startup. A step exceeding 120 seconds in either direction withholds Stratum work and solved publication until the clock comes back into range. Read `/status` at `mining.peer_clock` for independent SV network groups, measured offset and disagreement. At startup a corroborated offset beyond 120 seconds also holds work. Mainnet needs at least three groups to assess the clock through peers. Maintain an independently synchronized host clock while group coverage is unavailable. A failed durable checkpoint stops the process. Preserve the committed checkpoint and free storage before restarting. A leftover temporary snapshot can be ignored. [Measured clock and storage recovery](chronicle-results.md)

The default network is mainnet. The default API listens only on loopback. The peer identity persists in the data directory. Store that directory privately. Run one identity per node. A fresh identity has no special admission rights. Operators of other peers choose which announcements and assets they will consume.

| Option | Purpose |
| --- | --- |
| --network mainnet or regtest | Selects the BSV network, peer namespace and difficulty rule. |
| --peer MULTIADDR | Repeated static peers. Mainnet uses DNS bootstrap when this is omitted. Regtest uses explicit peers. |
| --listen MULTIADDR | Local libp2p bind address. |
| --data-dir PATH | Directory for the local peer identity. |
| --observe-bodies | Fetch available full block bodies and build the working set. Mining implies body observation. |
| --api-bind IP:PORT | Status and raw transaction intake. Default 127.0.0.1:8080. Keep this on a trusted interface. |
| --asset-bind IP:PORT and --asset-url URL | Bind the Asset service and advertise its externally reachable base including /api/v1. Required for mining. |
| --stratum-bind IP:PORT and --payout-script HEX | Serve mining work and specify the coinbase payout locking script. Enable only on a trusted network. |

Mainnet Stratum requires an authenticated alert gateway, an operator bearer token and a worker password. A mainnet observer exposing its operator API beyond loopback also requires the bearer token. The startup digest of the executable appears in `/status` under `release.executable_sha256` and in the shadow journal start record. The public Asset server is read-only. Use a trusted mining LAN or authenticated encrypted tunnel for plaintext Stratum. Issue distinct operator and worker credentials. The data-directory lock fences concurrent writers on the same filesystem. Each mining identity also holds an exclusive allocation lock for its network. The coinbase commits to the digest of the public identity, so independent miners using the same payout script have distinct search spaces.

Run `python3 qualification/operator_access.py .native/operator-access.json` against the release binary to check that the worker credential cannot read operator status, the operator credential cannot authorize a worker, the public server rejects writes, and the reported binary SHA-256 matches the executable. [Interface acceptance receipt](evidence/chronicle-operator-access.json)

For active/standby deployment, provision one persistent directory, writable only by the miner account, and pass the same filesystem to every potential active miner with `--mining-lease-dir PATH`. The filesystem must support mutually exclusive process locks across the participating hosts, atomic rename and durable file and directory sync. The default on a single host is `$XDG_STATE_HOME/scary-node/mining-leases`, falling back to `$HOME/.local/state/scary-node/mining-leases`. Mount this directory into containers independently of restored node data. During migration, stop older binaries that only lock the data directory and start from the most recent extranonce watermark. Use external host fencing before failover if a filesystem can split into independently writable partitions.

The miner durably reserves 1,024 connection numbers before issuing the first number in a range. A restored standby compares its bound allocation domain with the mounted record. An empty replacement authority or an active lock stops startup. Preserve the authoritative allocation directory when restoring a data backup. Rolling back both the authority and the data can repeat earlier ranges. [Crash and restore receipt](evidence/chronicle-mining-lease.json)

The body capacity defaults to 256 MiB. Set `SCARY_MAX_BLOCK_BYTES` according to host resources. `SCARY_MAX_TRANSACTION_BYTES` defaults to 16 MiB or the smaller body limit. `SCARY_MAX_WITNESSED_OUTPUTS` defaults to one million. An exhausted witnessed-output budget rolls back the body and withholds work. Increase capacity and restart to retry. The operator status reports the effective settings. The receiver keeps up to 1 MiB of a body in memory during transfer. Larger wire bodies spill into an anonymous file on the node data volume. Validation and the reorg journal share the completed read-only mapping. The snapshot embeds the body bytes for restore. Transaction indexes, witnessed scripts and undo entries still use memory. The recovery journal retains up to eight active bodies within its byte and item limits. A missing body or failed fetch interrupts work until coverage recovers. The node checkpoints its branch in the network data directory and verifies the checkpoint digest and retained bodies on restart. An explicit invalidation outside reversible ancestry withholds work. Inspect disk space, connectivity, signed sequence and selected parent before restarting a worker. Mainnet work needs 147 contiguous headers and at least one eligible spend.

The byte budget for the active undo journal, `SCARY_MAX_JOURNAL_BYTES`, defaults to the larger of 512 MiB and the configured block size. The separate competing-body buffer uses that same byte ceiling. `SCARY_MAX_UNDO_ITEMS` defaults to two million changes. If one block alone exceeds that undo budget, the node rolls its changes back, preserves the prior tip and reports the reason under `mining.suspended_reason`. Increase the budget and restart to recover the missing block. New snapshots encode bodies larger than 1 MiB in chunks of at most 1 MiB. Restores can also read the earlier single-binary encoding. Migrating a legacy body can temporarily allocate its full flat payload. On regtest, the new binary restored a 12,583,267-byte body and an earlier chunk-capable release read the new checkpoint and followed another stock SV successor. A separate run withheld work on undo exhaustion, restarted at the same tip and retrieved the missed parent. [Chunked restore and rollback](evidence/chronicle-chunked-restore.json) · [Undo capacity recovery](evidence/chronicle-undo-capacity.json)

The pending candidate pool defaults to 65,536 transactions and the smaller of 128 MiB and the block limit. Set `SCARY_MAX_PENDING_TRANSACTIONS` and `SCARY_MAX_PENDING_BYTES` for the intended workload. Admission reserves room for the actual coinbase, header and transaction count so existing work can still be solved when the pool fills. A P2SH payout script is refused at startup under SV Node’s local mining policy. [SV Node mining checks](https://github.com/bitcoin-sv/bitcoin-sv/blob/6504a3aff65ba97c0f6c80962b033e35ecbfed4b/src/rpc/mining.cpp#L841) · [Two-receiver capacity proof](evidence/chronicle-candidate-capacity.json)

Use `--sv-peer IP:PORT` to add an independent current-tip Bitcoin SV path. Mainnet body observation with no static SV peers uses the three SV Node v1.2.3 mainnet DNS seeds and up to four simultaneous discovery sessions. With explicit peers, `--sv-discovery` also enables rotating native SV paths. [SV Node DNS seeds](https://github.com/bitcoin-sv/bitcoin-sv/blob/6504a3aff65ba97c0f6c80962b033e35ecbfed4b/src/chainparams.cpp) Ordinary inputs need a witnessed creation and successor on the active branch or a validated in-template parent. BDK checks both policy and candidate consensus. Authorized confiscations are bound to exact bytes and height. Their recovered outputs can be spent 1,000 blocks after inclusion. [Build, receiver setup and operating contract](chronicle-qualification.md)

A competing branch beyond the retained undo data can establish a fresh witnessed boundary from a common eligible ancestor and greater verified work. Inspect the signed exclusion, recovery locator, body budget and rebuilt coverage when a deep fork interrupts work. [Deep recovery procedure and stock-node evidence](deep-recovery.md)

## Size the node for the measured workload

The four-node large-block trial used the following three overrides. Set them in the node's environment before startup and check the effective values under `/status` → `mining.capacity`.

```sh
export SCARY_MAX_BLOCK_BYTES=536870912
export SCARY_MAX_JOURNAL_BYTES=1073741824
export SCARY_MAX_UNDO_ITEMS=8000000
```

The 359,090,376-byte fixture exceeds the default 256 MiB body allowance. With the settings above, the entrant checked all 1.8 million signatures and payment values in that block. Scary's peak sampled container memory was 3.00 GiB. Stock SV Node, two Teranodes, two Aerospike databases and the entrant shared a 16-vCPU Linux ARM64 VM on a 16-core M3 Max with 128 GiB of physical RAM. The slowest of the four nodes selected the block after 86.93 seconds. The separate continuous-wallet trial settled 3,037.51 payments/s over 1,820.44 seconds. Stock mined its 75 offer-period blocks, and Scary had no eligible work in its 225 scheduled slots. Budget separately for simultaneous wallet intake, work issuance, persistent storage and block verification. ## Stop and restore the miner

Send SIGINT or, on Unix, SIGTERM for a controlled stop. The node closes new transaction admission and work issuance and writes an atomic checkpoint when its eligible pool or its waiting queue has changed since the last durable boundary. Allow enough time for a large outstanding snapshot to sync before a service manager escalates to a forced kill. On startup, inspect the restored parent and wait for a connected data peer to reconfirm it. An abrupt process or storage failure restores the last durable checkpoint. A native offer awaiting its funding block’s first successor reopens in the separate waiting queue with its original source and arrival order. Older checkpoints reopen with an empty waiting queue. Restoring a queue above the configured count, byte or per-transaction capacity stops startup with the corresponding reason. Restore sufficient capacity and reopen the same data directory.

An independent regtest halted the process after stock SV Node gossiped one eligible signed payment. The replacement stock peer held the same confirmed chain, had an empty mempool and sent zero transaction bytes. The original release reopened with zero eligible payments after both signals, and an authorized worker received no job. The corrected release exited successfully on both signals and restored the payment in both cases. The worker solved two separate 1,100-satoshi-fee blocks. The replacement stock node selected and extended each one. ## Inspect what the entrant knows

`--min-observed-blocks N` sets the minimum number of contiguous observed bodies before Stratum issues work. It accepts 1 through 147 and defaults to 1. The realistic regtest sets it to 13. Mainnet still requires the complete difficulty window. A ready observation window by itself supplies neither a payout script nor eligible transactions.

An eligible signed native payment whose witnessed funding lacks a successor can wait outside the template. The status reports `waiting_for_successor` and `waiting_for_successor_bytes`. The per-source `promoted_after_successor` counter records later admission. [Signed stock-peer comparison and receipt](early-peer-intake.md)

`GET /status` exposes the recent `mining.validation_window`. Each row binds its counters to a height and hash. Look at `known_inputs`, `unknown_inputs`, `script_checks_passed`, `amount_checks_passed`, `transactions_determinate`, `transactions_deferred` and `coinbase_reward_checked`. A row with deferred inputs can still have successful checks for the inputs the node knows.

Use `GET /outpoints/<display-txid>/<vout>` to inspect a single outpoint in the local working set. Use `POST /check-transaction` with raw transaction bytes to assess a payment against that state. The response explains the determinate, deferred or invalid result. This read-only call leaves the candidate pool untouched. Submit work through `POST /transactions` when you want the miner to include it. All three endpoints belong on the operator’s trusted interface. [Lab and metric definitions](scenario.md)

On the authenticated operator interface, `POST /transactions/batch` accepts an `application/octet-stream` body containing a CompactSize count from 1 through 4,096 followed by that many raw transactions. The complete request shares the individual transaction byte limit. Invalid framing returns HTTP 400 before any admission. A framed request returns HTTP 200 with an ordered `results` array. Each element contains a `txid` or an `error`. Offer parents before their children and check each result. Admission uses the same witnessed inputs, policy and directive checks as individual submission. Repeating an already pending eligible transaction returns its existing ID.

## Inspecting directive outcomes

The alert journal records each verified envelope as a numbered `.signed` file. A `.receipt` records the application revision and the exact local RPC result. Compare its sequence with `mining.durable_directive_sequence` before treating it as applied. A peer ban uses SV Node's default 24-hour lifetime from first local application. The journal preserves the original start time across restart. For older journal entries the migrator uses the signed file's local modification time. An unchanged freeze item has the SV Node result `already in consensus`. Other items in its signed batch can take effect. A rejected signed action has a `.failure` record with its reason and any structured RPC result. The operator can reconcile its sequence, hash and outpoint with the issuer. Mining readiness stays false while an action remains outstanding.

A consensus freeze applies when Scary Node attempts to connect a block. Once a frozen spend triggers a soft freeze, the block's hash carries that decision through its third successor. Updating the outpoint's freeze interval leaves an existing block hold in force and preserves already-connected blocks. A signed block invalidation removes the known branch and can select an eligible, previously buffered competitor immediately. If the invalidation reaches beyond reversible evidence, the node reports the boundary and withholds work. [SV Node freeze RPC](https://github.com/bitcoin-sv/bitcoin-sv/blob/6504a3aff65ba97c0f6c80962b033e35ecbfed4b/src/rpc/frozentxo_rpc.cpp#L371) · [SV Node soft freeze index](https://github.com/bitcoin-sv/bitcoin-sv/blob/6504a3aff65ba97c0f6c80962b033e35ecbfed4b/src/block_index.h#L542)

Each Stratum job retains its immutable coinbase, Merkle branches and a commitment to the ordered transaction prefix it covers. Every connection can keep 4,096 valid same-parent job commitments. At that bound the node coalesces new offers until space becomes available or the parent changes. Additional admissions preserve earlier prefixes. A pool rebuild after a directive recalculates them. A network-target solution reconstructs that exact prefix and checks the complete wire block before persistence and publication. Workers receiving the same revision share its prevalidated template.
